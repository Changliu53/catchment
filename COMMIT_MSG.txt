test: guard the blank-map regression at two layers

The map rendered nothing because MapLibre v6 loads its Web Worker as a
separate chunk and that URL did not survive bundling: the request fell back
to the document root and returned the 404 HTML page. The worker is what
turns GeoJSON into renderable tiles, so its absence explained every symptom
while the source, the layers, the paint expressions and the console all
looked correct.

Unit (src/lib/__tests__/maplibre-packaging.test.ts): assert the installed
maplibre-gl inlines its worker as a Blob, references no external worker
chunk, and stays on the major version whose entry does that. An upgrade
that reintroduces the packaging fails here rather than on the deployed map.

End-to-end (e2e/map.spec.ts, Playwright): load the page, click a preset,
assert queryRenderedFeatures() returns the features. That API can only
answer from tiles the worker produced, so it is a direct probe of what
broke. It runs against a production build on purpose — the fault was a
bundling fault and next dev served the worker fine.

The third spec is a negative control: it replaces window.Worker with an
implementation that constructs but never answers, and asserts the layers
still exist while nothing renders. A regression test that has never failed
is a guess about what it measures; this one reproduces the fault and shows
the probe going to zero.

/api/query is intercepted with a fixture, so neither suite needs
DATABASE_URL or an API key.
